### 可行性结论

> **可行。** 全部游戏资产可从 CDN 完整获取（实测核心资源 60/60 下载成功，音频 40/40 抽样成功），玩法逻辑 100% 位于客户端 JS，服务端接口仅 17 个且全部为存档 / 排行 / 帮会 / 支付类。工作量预估 **12 ~ 18 人日**。

### 关键技术判断

- **资源**：美术资产以 **4 张精灵图集**（car / person / goods / building，200px 网格）打包，非数千散图；PC 端 `hasImgHD()` 恒为 `true`，**自动加载 HD 图集**（car_HD 1.83MB / person_HD 1.77MB / goods_HD 1.08MB）。
- **数据**：`gamedata.json`（424KB）为**完整游戏规则库**，data-driven 设计，是离线化的关键抓手。
- **改造手法**：**不修改 `hun_min.js`**，改为猴补丁 `jQuery.ajax` + 17 条路径路由表拦截，配套 `SaveEngine` 落地 `localStorage`。
- **原生桥**：以 Electron 重实现 `jsbridge_android.callbackJs` 协议，支付走渠道 SDK。
- **镜像体积**：预估约 **30MB**。

### 不可避免的降级项

| 模块 | 原联网形态 | 单机化形态 |
|---|---|---|
| 帮会 PvP | 真实玩家对抗 | AI 模拟对手 |
| 排行榜 | 服务端实时榜 | 幽灵榜（本地生成） |
